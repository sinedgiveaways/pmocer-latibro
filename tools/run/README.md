# tools/run

Game runs and diagnostics of a running `build/orbitals-together`. Output goes to `build/run/` and `scratchpad/`. Heavy commands go
through `job.sh`.

| Script | What it does | Usage |
|---|---|---|
| `job.sh` | Runs a heavy command (a game run, a replay) through the host's job runner when there is one (`JOB_RUNNER`, or `job-runner` on PATH: memory cap and one at a time), else a systemd user unit capped at `JOB_MEM` without swap, else directly | `tools/run/job.sh run\|start NAME CMD...` |
| `watch.sh` | Follows a run's log and prints the lines matching a pattern, plus FATAL and guard stops; exits when the run ends (the command of a Monitor) | `tools/run/watch.sh NAME [PATTERN]` |
| `lan2.sh` | Two runs on one PC for LAN play (`ORBITALS_LAN=1`), each in its own network namespace inside a user namespace (no root), joined by a veth pair: A at 10.77.0.1, B at 10.77.0.2, B with its profile copy `build/profile-b`; one job unit caps the pair (`JOB_MEM`, 14G) | `tools/run/lan2.sh NAME [SECONDS]`, then `ctl.sh NAME-a`/`NAME-b ...`, `ctl.sh NAME stop` |
| `ctl.sh` | Sends a command to that run and waits for its answer: `frame`, `shot PATH` (whole screenshot and `PATH-s.png` 1280 wide for viewing), `dump DIR [ubo|lut]` (dump of the next frame), `flight`, `mem ADDR SIZE PATH` (game memory to a file), `tex ADDR` (textures over that address; 0: pool images larger than their storage), `press <ticks> <button> [hold]`, `stop` | `tools/run/ctl.sh NAME COMMAND...` |
| `flicker.sh` | Counts the frames with a black lower half in the 600 thumbnails up to a frame of a live run (title scene flicker) | `tools/run/flicker.sh NAME [FRAME]` |
| `ab.py` | A/B inside a run: with `ORBITALS_AB=<s>` blocks A and B alternate (A B B A; B A A B with `ORBITALS_AB_INVERT=1`) from the race start, and a switch `ORBITALS_<X>=ab` only acts in the B blocks; compares the 60-frame windows that are entirely A or entirely B and, with normal and inverted runs, gives the change with the scene balanced. Between two identical runs there is up to 12 ms per frame of noise | `uv run tools/run/ab.py build/run/NAME.log` |
| `run_perf.sh` | `build/orbitals-together` (or another executable with `ORBITALS_RUN_BIN`, e.g. a player folder's) under `perf record` (flat) with a GPU memory cap, and the 40 hottest symbols; opens the control FIFO (`ctl.sh` works with it) | `tools/run/run_perf.sh NAME [SECONDS]` |
| `texms.sh` | Total render thread time in texture uploads (and ASTC) up to a frame, from a run's `perf` lines, and the worst frame | `tools/run/texms.sh build/run/NAME.log [FRAME]` |
| `perf_split.sh` | Splits a profile by owner (game code, runtime, drivers) and lists the 15 hottest game functions | `tools/run/perf_split.sh FILE.perf` |
| `kstacks.py` | Where each thread sleeps inside the kernel (stacks of `perf record -e cs -g` with kallsyms names) and the `mmap_lock` waits per thread and call | see its header (kallsyms needs root) |
| `crit_path.py` | Critical path of each frame of an `ORBITALS_CRIT` recording (with `ORBITALS_TRACE=sched`): which thread and which state (running, waiting for a core, host call, wakeup latency) takes each ms between two presents (from totk-pc-recomp, MIT) | `uv run tools/run/crit_path.py FILE.bin` |
| `locks.py` | Wait on each runtime lock during the race, in ms per second, per lock, per requester and per holder while another waited (`ORBITALS_LOCK_PROF=1`), with `build/orbitals-together`'s names | `uv run tools/run/locks.py build/run/NAME.log` (Windows: `--exe build/dist/windows/orbitals-together.exe`) |
| `perf_sdk.py` | How much CPU the recompiled SDK code takes in a profile, per thread and per namespace (`nn::os`, libc, math…), with `build/bindb.sqlite`'s names | `uv run tools/run/perf_sdk.py scratchpad/NAME.perf` |
| `sample_stacks.sh` | Stack snapshots through gdb when `perf` does not record call graphs (`ORBITALS_ALLOW_PTRACE=1`) | `tools/run/sample_stacks.sh DIR [N] [GAP]` |
| `gpu_ok.sh` | Refuses when amdgpu logged since boot a failed ring reset or a full GPU reset (after a failed reset, the next replay froze the machine); episodes recovered in the ring, however many, let it go on. Called by `run_perf.sh` and `replay.sh`, which set `ORBITALS_GPU_GUARD=1` | `gpu_ok.sh` |
| `avail.sh` | MB available for a run: `MemAvailable` plus `GPUReclaim` (TTM page pool the kernel releases under pressure); used by the thresholds of `run_perf.sh` and `replay.sh`; `--wait FLOOR` waits up to `WAIT_MEM` minutes for it | `avail.sh`, `WAIT_MEM=30 tools/run/run_perf.sh NAME` |
| `memwatch.sh`, `memtop.sh` | RSS, swap, GTT and VRAM every 5 s; memory maps with their Rss after N seconds | `memwatch.sh OUT.tsv`, `memtop.sh AT OUT` |
| `stacks.py` | Stacks of every thread of a running `build/orbitals-together`, with the game's names | see its header |
| `summary.py` | A log summed up in ~15 lines: how it ended, last frame and phases, median and p95 frame time before and during the race, VRAM peak, `ORBITALS_HOST_TIME` census, grouped failures and the game speed (a warning when the race runs in slow motion) | `uv run tools/run/summary.py build/run/NAME.log [...]` |
| `gpucmp.py` | The race's GPU time of several runs side by side: median `gpu avg` and interval per 60-frame window in the race, whole `ORBITALS_PASS_TIMING=1` windows in the race (busy and the largest pass) and the last texture memory; for changes without an in-run switch (`ORBITALS_ASTC_BC1`) | `uv run tools/run/gpucmp.py build/run/NAME.log [...]` |
| `why.sh` | Sourced by `run_perf.sh`: under Claude Code (`CLAUDECODE=1`) a run without `ORBITALS_RUN_WHY` (what I expect to see and what I conclude from each result) is refused and the captures of `build/cap` are suggested; each reason goes to `build/run/why.log` | `ORBITALS_RUN_WHY="…" tools/run/run_perf.sh NAME` |
| `kwin-rule.sh` | KWin rule for our runs' windows (app id `orbitals-together-run`, `ORBITALS_BACKGROUND_WINDOW=1`): they never take the focus and open below the others; the player's window is not touched | `tools/run/kwin-rule.sh [--remove]` |
| `wine.sh` | An `.exe` (`build/orbitals-together.exe`, a self-test) in Wine with its own prefix in `build/win/wineprefix`, without Mono or Gecko: it shows no dialogs and does not touch `~/.wine`. Its `Desktop` is your desktop folder (Wine links it in every new prefix): what a test creates on the desktop (a `.lnk`) is deleted by hand | `tools/run/wine.sh PROGRAM.exe [ARGS...]` |
| `envs.py` | Catalogue of the `ORBITALS_*` variables the runtime reads (`cfg_get` and `rt_knob`): where and their comment, taken from the code | `uv run tools/run/envs.py [REGEX]` |
| `sym.py` | Names the `build/orbitals-together` addresses of the log (`exe+`, `mkw+`, base 0x200000) and, for translated code, its game function | `uv run tools/run/sym.py DIR...` or `< build/run/NAME.log` |
| `analyze_timeout.py`, `Analyze-Timeout.ps1` | A read-only summary of the threads around an Unreal RenderThread timeout in `logs/orbitals.log` (Python, and the same for Windows PowerShell without Python) | `python tools/run/analyze_timeout.py logs/orbitals.log [--all-threads]`, `.\tools\run\Analyze-Timeout.ps1 .\logs\orbitals.log [-AllThreads]` |
| `shader_analyzer.py` (`shader_analyzer.exe` on Windows, built by CI) | A report of a whole `orbitals.log`: how the run ended, key threads, shaders without SPIR-V, NVN sync call sites, SDK gaps; Markdown or JSON ([log-analyzer.md](../../docs/log-analyzer.md)) | `python tools/run/shader_analyzer.py --input logs/orbitals.log [--output report.md]` |
| `testdata/` | `sample-orbitals.log`, a small synthetic log (no game file) that CI's smoke test of `shader_analyzer.exe` reads |
